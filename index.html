Let a web page tell an agent what it can do.

WebMCP is a browser API. A page registers its own functions as tools, each with a name, a description and a schema. An agent in the browser calls those tools instead of guessing its way through the page's buttons and forms. The user stays on the page, logged in, watching it happen.

What it is

The problem

Agents that act on the web today either scrape the user interface, which is slow and fragile, or talk to a separate backend through the Model Context Protocol or OpenAPI, which bypasses the page and makes the developer duplicate the user's state and login on a server.

The idea

Put the tools in the page. The page's own JavaScript registers tools through document.modelContext. A built-in browser agent, an extension or a trusted iframe discovers them and calls them. Page UI, agent and user share one context.

The shape

A tool is a function with a natural-language description and a JSON Schema for its input, the same shape MCP tools use. A declarative form-based variant is being explored alongside, but the imperative API is what the specification defines today.

How it works

  1. 1
    Register. The page calls registerTool() with a name, description, input schema and an execute callback. An AbortSignal unregisters it later.
  2. 2
    Discover. An agent connected to the page asks the browser for the current list of tools and their schemas.
  3. 3
    Invoke. The agent requests a call with structured arguments that match the schema.
  4. 4
    Execute. The browser mediates the call and runs the page's callback in the page's own context, with the user's session and state.
  5. 5
    Respond. The callback returns structured content to the agent, which carries on with the user.

Sites can switch the feature off with Permissions-Policy: tools=(). Tools in cross-origin iframes are only visible where exposedTo allows. See the spec's security and privacy considerations.

The webmcp package on npm

webmcp on npm has been held since February 2025 and is being developed into a small JavaScript library, with its source at github.com/webmcp/webmcp. It sits beside the official polyfill rather than replacing it.

  • 0.0.1, published 2 February 2025: name reserved.
  • 0.0.2, next: a sensible first release with a repository link, a README, and a helper over document.modelContext, plus a live demo page on this site.

Ideas on direction are welcome by issue on the repository.
